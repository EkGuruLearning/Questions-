Where should this file go?

A practical, topic-wise map of the repository: where to put a new file, which catalogue makes the website read it, and how to check a future repository merge before finishing it.

यह पेज बताता है कि नई PDF, सवाल, नक्शा, रिपोर्ट या वेबसाइट पेज किस फ़ोल्डर में रखना है। सिर्फ़ फ़ाइल कॉपी करने से वह वेबसाइट पर अपने-आप प्रकाशित नहीं होती।

One read / merge-check command

From the repository root, read the folder map or run the read-only structure preflight:

python3 tools/read_structure.py
python3 tools/read_structure.py --check

--check merge conflicts, expected folders, generated catalogues, website links, asset paths और subject gates जांचता है। यह फाइलों को move/overwrite नहीं करता।

What the browser reads

Source → builder → website

Pages and shared design

Route HTML is in index.html, subjects/, maps/, practice/, study-material/, sources/ and guides/. Catalogue pages share assets/css/site.css and assets/js/app.js.

Editable source catalogues

data/catalog/books.json, subjects.json and portal_resources.json describe files and topics. Keep exact, case-sensitive repository paths and explicit source/status notes here.

Generated website manifests

tools/build_catalog.py creates assets/catalog/subjects.json, resources.json, and maps.json. The browser catalogue reads these generated manifests; it does not crawl every folder.

Computer Network questions

The CN builder reads canonical question/source inputs and emits assets/banks/cn/manifest.json plus hash-named topic chunks. The practice app reads the manifest and selected topic chunk—not arbitrary files in Incoming/.

Practice-app catalogue

tools/build_site_data.py updates assets/catalog.min.json and CN bank outputs from the canonical sources/catalogue. Do not edit generated chunks or the compact catalogue directly.

Geography map gallery

A new CSV/document can be registered in data/catalog/portal_resources.json. A new gallery map also needs an explicit reviewed record in tools/build_catalog.py’s map builder, alternative text and a source/QA status; a loose image is not enough.

आसान तरीका: नई फ़ाइल website पर कैसे दिखेगी?

  1. CN की नई topic PDF को सही Computer Network/Topics/TNN/ folder में रखें। नया question-source PDF हो तो उसे Computer Network/Incoming/ में रखें—वह review के बिना publish नहीं होगा।
  2. Topic PDF का exact path और सही topic_id data/catalog/books.json में लिखें; उसी ID को CN की book_ids list में भी जोड़ें।
  3. python3 tools/build_site_data.py और python3 tools/build_catalog.py चलाकर generated files फिर से बनाएँ।
  4. python3 tools/read_structure.py --check चलाएँ। PASS आने के बाद release tests और diff review करें।
  5. Geography के files अपने audited source folder में ही रखें। दोनों Rajasthan geography folders को आपस में न मिलाएँ; नई CSV/report को data/catalog/portal_resources.json में register करें।

Source files vs generated files

Editable source / source of truth

data/catalog/*.json, question-review sources, source registers, original PDFs, original maps/CSVs/audits, route HTML, and shared code. Review provenance before changing them.

Generated browser data / reports

assets/catalog/*.json, assets/banks/cn/*, assets/catalog.min.json, build manifests and repository inventories. Rebuild them; do not patch output by hand.

Not automatically student-facing

Incoming/, Computer Network/new/, Material Archive/, tools/, tests/ and archive/. These folders are staging, source, QA or preserved history.

Geography source trees are separate

Rajasthan Geography Maps/ and Geography/Map/Rajasthan/ have different READMEs/audits. Keep both, their paths and their claims distinct; unresolved boundaries stay Needs verification.

For a future repo merge

Safe merge checklist

  1. Fetch and inspect the incoming repository first. Check its tree and overlapping paths; do not copy a nested repository root over this repository.
  2. Preserve original paths. Resolve duplicate names deliberately, keep the two geography trees separate, and never replace generated outputs with copied stale manifests.
  3. Register each website file in the source catalogue. Rebuild generated manifests before checking them.
  4. Run the one-command preflight and the release tests before completing a merge on the intended feature branch.
git fetch <remote> <branch>
git log --oneline --left-right HEAD...FETCH_HEAD
git diff --stat HEAD...FETCH_HEAD
git merge --no-commit --no-ff FETCH_HEAD

# Resolve any intentional path conflicts, then regenerate source-derived outputs:
python3 tools/build_site_data.py
python3 tools/build_catalog.py
python3 tools/read_structure.py --check
python3 tools/run_release_checks.py
git diff --check

# If anything is wrong before finishing the merge:
git merge --abort

The merge command is a template; replace <remote> and <branch> with the reviewed repository/branch. Do not merge into main before review. --check is read-only; the builders above it intentionally regenerate derived files.

अगर preflight fail हो, merge पूरा न करें। पहले path/catalogue ठीक करें या चालू merge को git merge --abort से वापस लें।
